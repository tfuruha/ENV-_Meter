# 実装計画: センサーをBMP585へ変更するフォークの作成

## 1. 目的
M5Stack Basic向けの環境モニタ（`ENV _Meter`）プロジェクトにおいて、使用するセンサーをSHT30/QMP6988からAdafruit BMP585（`ENV _Meter_TQT`で使用実績あり）へ変更する。
これに伴い、湿度の取得・表示機能を削除し、温度・気圧のみを扱うようにコードベースと仕様書を修正する。

## 2. 分析（現状分析 vs 理想の状態）
### 現状 (`ENV _Meter`)
- **ターゲット**: M5Stack Basic
- **センサー**: SHT3X (温度・湿度), QMP6988 (気圧)
- **依存関係**: `m5stack/M5Unit-ENV`
- **UI**: 温度 (Y=40)、湿度 (Y=100)、気圧 (Y=160) の3項目を表示
- **更新ロジック**: 1秒に1回、タイマー(`updateTimer`)で同期的にセンサーデータを取得し表示。

### 理想の状態
- **ターゲット**: M5Stack Basic (維持)
- **センサー**: Adafruit BMP585 (温度・気圧)
- **依存関係**: `Adafruit_BMP5xx`
- **UI**: 温度と気圧の2項目のみ表示（レイアウトはヒアリング結果に基づき調整）
- **更新ロジック**: `ENV _Meter_TQT`を参考に、25ms周期(`pollTimer`)でデータレディを非同期に確認・取得し、1秒周期(`updateTimer`)で画面を更新する完全非ブロッキング構造（`embedded_rules.md`に準拠）。

## 3. 提案される変更

### 対象ファイルと変更内容

1. **`platformio.ini`**
   - `lib_deps`から `m5stack/M5Unit-ENV@^1.0.1` を削除。
   - `lib_deps`に `https://github.com/adafruit/Adafruit_BMP5xx.git` を追加。

2. **`doc/SpecSammary.md`**
   - 使用ハードウェアのセンサー記述を「Unit ENV-III」から「Adafruit BMP585」へ変更。
   - アプリケーション仕様から「湿度」に関する記述と画面のモックアップを削除・修正。

3. **`src/main.cpp`**
   - **インクルードと変数**:
     - `SHT3X.h`, `QMP6988.h` を削除し、`Adafruit_BMP5xx.h` を追加。
     - `current_hum` グローバル変数を削除し、`Adafruit_BMP5xx bmp;` と `IntervalTimer_m pollTimer(25);` を追加。
   - **表示ロジック (`DisplayItem`)**:
     - `displayItems` 配列から湿度の項目を削除。
     - Y座標を調整（ヒアリングで決定）。
   - **初期化 (`setup()`)**:
     - I2Cピンは `21, 22` を維持。
     - 既存センサーの初期化処理を削除し、`initBMP585()` 関数（`ENV_Meter_TQT`相当、OversamplingやODR 10Hz設定等）を移植・実行。
   - **メインループ (`loop()`)**:
     - 25ms周期の `pollTimer` で `bmp.dataReady()` を監視し、データ取得成功時に `measurement_flag` を立てる。
     - 1秒周期の `updateTimer` で、`measurement_flag` が立っている場合に表示を更新する。
     - スリープ・復帰ロジック（`sleepTimer`）は現状のまま維持。

### 検証計画
- `pio run` でビルドが通ることを確認する。
- 実際のM5Stack Basic実機とBMP585をI2C (SDA=21, SCL=22)で接続し、温度と気圧が正しく表示されること、湿度が消去されていること、5分で画面がスリープ・復帰することを確認する。

## 4. リスク評価
- **I2Cアドレスの不一致**: BMP585のアドレスが `0x47` と `0x46` のどちらに設定されているかによって初期化が失敗する可能性がある。`ENV _Meter_TQT`と同様に両方をフォールバックで試行するロジックを組むことで回避する。
- **UIレイアウトの崩れ**: 項目が減ることで画面がスカスカに見えるリスク。適切なY座標の再配置が必要。
