# 減圧装置用 圧力モニター ソフトウェア設計書

## 1. システム概要
本システムは、自由研究などで使用する減圧装置の内部圧力（および周囲の温度）をリアルタイムで安全に監視するための**圧力モニター**です。  
M5Stack Basic と Adafruit BMP585 センサーを用いて現在の温度・気圧を取得し、ディスプレイ上に分かりやすく表示します。バッテリー駆動を考慮し、一定時間操作がない場合に本体の電源を切る省電力機能（パワーオフ機能）も備えています。

## 2. ハードウェア構成
- **メインボード**: M5Stack Basic (v2.6)
- **センサーモジュール**: Adafruit BMP585 (温度・気圧)
- **接続**: M5Stack 標準 Grove ポート (Port A: I2C通信 SDA=21, SCL=22)

## 3. ソフトウェア構成
### 3.1. 開発環境と依存ライブラリ
- **フレームワーク**: Arduino (PlatformIO)
- **依存ライブラリ**:
  - `m5stack/M5Unified` (画面描画・ボタン入力管理・電源管理)
  - `Adafruit_BMP5xx` (センサー制御用: `BMP585`)
  - `OpenFontRender` (日本語フォント描画用)

### 3.2. ファイル構成
- `src/main.cpp`: メインロジック（UI制御、センサー取得、パワーオフ管理）
- `include/binaryttf.h`: 日本語フォント（NotoSansJP-Regular）のバイナリ配列
- `include/util.h`: 周期判定・ワンショット判定用のユーティリティクラス（`IntervalTrigger_m`, `OneShotTrigger_m` など）
- `include/AlarmManager.h`: 圧力過剰低下警報機能（状態判定、スヌーズ、ビープ音制御）を管理するクラス（ヘッダオンリー実装）
- `include/HoldManager.h`: ホールド機能（開始・解除のトグル制御および測定値のラッチ・保持）を管理するクラス（ヘッダオンリー実装）

## 4. 主要ロジック設計

### 4.1. 画面描画設計
- **状態表示・ガイドラベル設計**:
  - 状態表示（Y=5, フォントサイズ24）: 現在の状態に応じて以下の文字列を描画。
    - 通常計測時: `[計測中]` (緑字 `TFT_GREEN`)
    - ホールド時: `[ホールド中]` (赤字 `TFT_RED`)
    - 圧力低下警報発報時: `[圧力低下警報]` (赤字 `TFT_RED`)
    - 警報スヌーズ中: `[警報スヌーズ]` (黄字 `TFT_YELLOW`)
  - 気圧数値表示色:
    - 通常時 / ホールド時: **シアン (Cyan)**
    - 警報発報時: **赤 (Red)**
    - スヌーズ時: **黄 (Yellow)**
  - ボタンラベル（Y=200, フォントサイズ24）: `BtnA` の上部（X=20またはX=40付近）に `ホールド` または `解除` を描画。

- **描画最適化（チラツキ防止）**:
  画面全体をクリア（`M5.Lcd.clear()`）すると、SPIバス経由の描画負荷によりチラツキが発生するため、以下の手法を採用しています。
  - **静的部分の分離**: 項目名や単位など、変化しないテキストは `drawStaticPart()` 内で `displayItems` 配列をループし、初期化時のみ一括描画します。
  - **数値部分の差分更新**: 毎秒の更新時は `drawValues()` 内で配列をループし、数値が表示されている矩形領域のみを `M5.Lcd.fillRect()` で塗りつぶして消去した上で、新しい値を上書きします。これにより書き換え範囲を最小化し、チラツキを解消しています。

### 4.2. センサー読み取りロジック（非ブロッキング＆ポーリング）
- **ポーリング間隔**: 25ms (`pollTimer` を使用)
- **更新間隔**: 1秒（`updateTimer` を使用）
- センサー（BMP585）のODR 10Hzに同期し、メインループ内で非同期に `bmp.dataReady()` を監視してデータを取得します。内部での気圧データは **hPa** 単位でそのまま保持・管理します。
- 新しいデータが取得済み（`measurement_flag == true`）の場合のみ、1秒周期で画面の再描画を行います。データ取得時には `alarmMgr.check(current_prs)` による気圧警報判定も即時行われます。

### 4.3. エラーハンドリング
センサー通信エラーに対するフォールバック処理を実装しています。
- **通常計測時**:
  - 正常取得時: 取得した数値を表示。
  - 単発エラー: エラーカウンタをインクリメントし、**前回の数値を保持**したまま表示を継続します。
  - 連続エラー (5回以上): 通信が完全に切断されたと判断し、すべての数値部に `Err` を表示します。正常な通信が復帰した時点で自動的に数値表示に戻ります。
- **ホールド動作中**:
  - バックグラウンドでのエラー検知は継続されますが、画面表示には一切影響を与えず、ホールドされた数値を維持し続けます。ホールド解除時に最新のエラー状態が画面へ即座に反映されます。
- **起動時**: エラーカウンタを初期値 `5` に設定しているため、初回データ取得までは `Err` または `Starting...` 状態となります。

### 4.4. ホールド動作仕様（イベント時の圧力記録）
実験中に変化や現象が発生した瞬間（イベント発生時）の圧力を記録し、画面上に固定（保持）して確認できるようにする機能です。
- `HoldManager` クラス（`holdMgr`）によって状態と保持値を管理します。
- M5Stackの `BtnA` (左側ボタン) を押した際に `holdMgr.toggle(current_tmp, current_prs)` を呼び出し、ホールドの開始・解除を切り替えます。
  - **警報が鳴っている間は例外**: `BtnA` を含む全ボタンの押下が警報の消音（スヌーズ）処理に割り当てられるため、ホールド操作は行われません。
- ホールド開始時にその瞬間の測定値を内部変数（`heldTmp_` / `heldPrs_`）に記録し、`drawValues()` で固定表示します。

### 4.5. 圧力過剰低下警報機能仕様（容器破損リスクに対する通知）
減圧実験において、容器内の圧力が過剰に低下すると**容器が外気圧に耐え切れず破損（潰れや破裂）するリスクが急増**します。安全管理のため、このような圧力異常を検知してユーザーに即座に通知する機能を `AlarmManager` クラス（`alarmMgr`）にて実装しています。

**状態遷移:**
```
IDLE --(prs <= 700)--> ALARM --(button)--> SNOOZE
  ^                      |                    |
  +-(prs >= 710)---------+-(prs >= 710 or timeout)+
```

- **発報条件** (`check()`): リアルタイム測定気圧 `current_prs` <= **700.0 hPa** のとき、IDLE状態であれば ALARM へ遷移し即時ビープ音を開始します。
- **自動復帰条件** (`check()`): リアルタイム測定気圧 `current_prs` >= **710.0 hPa** のとき、ALARMまたはSNOOZE状態であれば IDLEへリセットし、ビープ音を停止します（ヒステリシスによりチャタリングを防止）。
- **判定対象**: ホールド機能の有効・無効に関わらず、常にバックグラウンドで更新される `current_prs` を判定対象とします。
- **ビープ音出力**:
  - 周波数: 2000 Hz（`BEEP_FREQ_HZ`）
  - 鳴動時間: 100 ms ON（`BEEP_DURATION_MS`）
  - 発声周期: 500 ms間隔（`BEEP_INTERVAL_MS`、`beepTimer_` による非ブロッキング間欠制御）
- **ボタン解除（スヌーズ）機能** (`handleButton()`):
  - 警報鳴動中（ALARM状態）にいずれかのボタン（`BtnA`, `BtnB`, `BtnC`）を押下すると `alarmMgr.handleButton()` が呼ばれ、警報音を停止し60秒間（`SNOOZE_MS`）のスヌーズ状態（SNOOZE）へ移行します。
  - 警報鳴動中のボタン押下時は、ホールド切替等の通常ボタン機能は作動させず、スヌーズ（消音）処理のみを最優先で実行します。
- **ループ更新処理** (`update()`):
  - `loop()` の各周期で `alarmMgr.update(current_prs)` を呼び出し、以下の2つの判定を行います。
    1. **スヌーズタイムアウト判定**: SNOOZE状態で60秒が経過すると `snoozed_` をリセットし、気圧がまだ閾値以下であれば ALARM へ再遷移してビープ音を再開します。タイムアウト発生時は気圧の回復有無に関わらず `true`（再描画要求）を返します。
    2. **間欠ビープ判定**: ALARM状態（非SNOOZE）のとき、`beepTimer_` の周期到来でビープ音を発声します。
- **各メソッドの戻り値**: `check()`・`handleButton()`・`update()` はいずれも `[[nodiscard]] bool` を返し、`true` の場合に呼び出し元（`main.cpp`）が `drawStatusAndLabels()` および `drawValues()` を実行して画面を更新します。クラス自身は描画処理を持ちません。

### 4.6. 省電力機能（パワーオフ制御）
USB接続のバッテリーパック駆動を考慮し、電源の制御を行います。
- **パワーオフ移行**:
  - 最後のボタン操作から **5分 (300,000ms)** 経過で、`M5.Power.powerOff()` を呼び出してデバイスの電源を完全に遮断（パワーオフ）します。（`OneShotTrigger_m` を使用）
- **パワーオフからの再起動**:
  - デバイスがパワーオフ状態になるため、ソフトウェア（ボタン押下イベント）による復帰はできません。再起動するには、M5Stack側面の物理電源ボタン（赤）を押す必要があります。
