# BMP585 初期化およびステータス管理 設計書

## 1. 背景と目的
本設計書は、減圧容器の圧力メーターアプリケーションにおける、BMP585気圧センサーの初期化手順およびデータ取得タイミングを管理する割り込み（ステータス）設定の考え方を定義する。
Adafruit BMP5xxライブラリの内部挙動を補完し、I2Cバスの通信負荷を抑えつつ、安定したデータ取得とノイズ・消費電力対策を両立させることを目的とする。

## 2. センサー測定パラメータの基本方針
「大気圧からゆっくり減圧し、イベント発生の瞬間にボタンで値をホールドする」という要件に対し、人間の目視と操作反応速度（約0.2〜0.5秒）に最適化した設定を行う。

* **OSR（オーバーサンプリング）**: 圧力 128倍 / 温度 4倍
  * ノイズを極限まで減らすための最高解像度設定。
* **ODR（出力データレート）**: 10Hz (100ms周期)
  * 上記のOSR設定で実現可能な上限レート。
* **IIRフィルター**: 係数3（温度・圧力共通）
  * ステップ変化に対する90%追従時間が約0.5秒弱（5〜10サンプル）となり、人間のボタン操作のタイミングと測定値のラグが最も少なくなる最適なバランス。
* **パワーモード**: NORMALモード
  * 10Hz周期で自律的に「測定」と「スタンバイ」を繰り返す。

## 3. configureInterrupt() による初期化の考え方
マイコン側から無駄なレジスタ読み出し（ポーリング）を行うのを防ぐため、センサーの `dataReady()` 関数を用いて、新しいデータが準備できた瞬間にだけデータを取得する設計としている。
これを正しく機能させるため、初期化の最後に `configureInterrupt()` を実行し、以下の2つの対策を行っている。

### 3.1. データレディフラグ（Data Ready）の再有効化（ライブラリ仕様の回避）
**【課題】**
Adafruitライブラリの `begin()` 処理内部で Bosch APIが呼び出される際、仕様上内部の `INT_SOURCE` レジスタが一時的にクリアされ、データレディフラグの発生自体が無効化されてしまう問題がある[*2]。これにより `dataReady()` が常に `false` を返し続ける現象が発生する。

**【対策】**
初期化の最後に `configureInterrupt()` を明示的に呼び出し[*2]、引数に `BMP5XX_INTERRUPT_DATA_READY` を指定することで、ハードウェアのデータレディフラグを再有効化する。

### 3.2. 未接続 INT ピンの電位固定（ハードウェア制約への対応）
**【課題】**
本システムの基板上において、BMP585の `INT` ピンはどこにも接続されていない（未接続状態）。データシートによれば、INTピンが出力未設定のままフローティング状態になると、内部ノイズの発生や不要な消費電流の増加を招く恐れがある[*1]。

**【対策】**
`configureInterrupt()`[*2] の設定において、INT ピン出力を**「有効 (`true`)」**かつ**「プッシュプル出力 (`BMP5XX_INTERRUPT_PUSH_PULL`)」**に設定する。これにより、マイコン側で物理ピンを接続していなくても、センサー内部で電位がHigh/Lowに明確にドライブ（固定）され、動作の安定化と省電力化が図られる[*1]。

---

### 参考：`configureInterrupt()` のパラメータ設定値一覧
`src/main.cpp` における実際のコード設定は以下の通り。

```cpp
bmp.configureInterrupt(
    BMP5XX_INTERRUPT_LATCHED,    // 割り込みラッチ：LATCHED（クリアされるまで保持）
    BMP5XX_INTERRUPT_ACTIVE_HIGH,// ピン極性：ACTIVE_HIGH
    BMP5XX_INTERRUPT_PUSH_PULL,  // 出力駆動：プッシュプル
    BMP5XX_INTERRUPT_DATA_READY, // 割り込みソース：データレディ
    true                         // INTピン出力：有効（未接続時の電位固定用）
);
```

## 4. 実装・設計上の注意点

### 4.1. 設定順序の遵守
`configureInterrupt()` は、必ずOSR、ODR、IIRフィルタなどの**各種センサー設定をすべて完了した一番最後**に呼び出すこと。
センサーの設定変更時には内部でデータやFIFOのフラッシュ処理が走り、割り込みステータスが意図せずリセットされる可能性があるため、すべての測定パラメータ確定後に割り込み・ステータス設定を行う必要がある。

### 4.2. Clear-on-read 仕様とポーリングの排他制御
BMP585の割り込みステータスレジスタ（`INT_STATUS`：`0x27`）は**「Clear-on-read（読み出すと同時にフラグが自動的にクリアされる）」**というハードウェア仕様である[*1]。

* `bmp.dataReady()` を呼び出すと、内部で `INT_STATUS` レジスタが読み出されるため、フラグは即座にクリアされる[*2]。
* したがって、複数箇所（例：タイマー割り込み内とメインループの両方）で `dataReady()` や `performReading()` を実行すると、一方の呼び出しでフラグが横取りされて他方で検出できなくなる。
* 現在の `main.cpp` のように、`millis()` を用いたソフトウェアタイマー（25ms周期）により**メインループ内の一箇所のみでステータスを確認し、フラグが立っていたときだけデータを読み出す設計**を徹底すること。
